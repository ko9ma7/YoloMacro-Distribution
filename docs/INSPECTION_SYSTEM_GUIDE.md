# YOLO·AOI 검사 설비 구성 가이드

YoloMacro는 매크로 실행, 대상 창 또는 카메라 영상 취득, YOLO 객체 검사, AOI 이상 검사, 라벨 검수를 하나의 흐름으로 연결합니다. 단순 클릭 자동화와 검사 설비 운전을 분리하지 않고, 같은 검사 결과를 관찰·판정·분기·입력 동작에 재사용하는 것이 기본 구조입니다.

## 1. 검사 영상 입력

`대상 > 검사 영상 입력` 또는 `설정 > 검사 영상 입력`에서 프레임 원천을 선택합니다.

| 입력 | 용도 | 설정 |
|---|---|---|
| 선택한 대상 창 | 기존 프로그램, 시뮬레이터, 장비 HMI 검사 | 타겟 설정, 캡처 방식 |
| 특정 카메라 | USB/DirectShow 카메라의 실물 검사 | 장치 검색, 장치 번호, 요청 해상도, 미리보기 |

카메라는 별도 `CameraCaptureService`가 열기·프레임 취득·해제를 담당합니다. YOLO, AOI, 캡처 편집기, ROI 선택, 라벨용 이미지 수집은 모두 현재 선택된 입력을 사용합니다.

카메라만 선택한 상태에서는 관찰 검사와 결과 기록을 실행할 수 있습니다. 마우스 클릭, 키 입력, 스크립트처럼 대상 창을 제어하는 액션이 있으면 실행 전에 경고하고 중단합니다. 카메라 검사 후 HMI를 조작해야 한다면 카메라 입력을 유지한 채 대상 창도 별도로 지정합니다.

> 현재 카메라 어댑터는 Windows DirectShow 기반입니다. GigE Vision/GenICam, 하드웨어 트리거, 조명 컨트롤러, PLC I/O, 다중 카메라 동기화는 장비 SDK에 맞는 별도 어댑터가 필요합니다.

## 2. 라벨 검수 상태

라벨 이미지는 다음 세 상태로 관리합니다.

| 상태 | 의미 | 내보내기 |
|---|---|---|
| 작업중 | 라벨 작성 또는 수정 중 | 품질 검사에서 미검수로 표시 |
| 검수 완료 | 객체와 클래스 확인 완료 | YOLO 객체 라벨로 내보냄 |
| 정상/빈 이미지 | 검사했지만 대상 객체가 없음 | 빈 `.txt` 라벨로 내보냄 |

라벨 화면에는 전체 이미지, 검수 완료, 정상/빈 이미지, 작업중, 객체 수, 클래스 수, 클래스별 객체 분포와 완료율이 표시됩니다. 상태 필터와 `다음 미검수` 버튼으로 검수 대기 이미지만 연속 처리할 수 있으며, 이미지별 검수 메모와 검수 시각도 데이터에 저장됩니다. 라벨을 추가·수정·삭제하면 해당 이미지는 자동으로 `작업중`으로 돌아갑니다.

## 3. 데이터셋 품질 검사

내보내기 전에 다음 항목을 검사합니다.

- 존재하지 않거나 읽을 수 없는 이미지
- 이미지 밖으로 벗어난 박스, 너무 작은 박스, 잘못된 클래스
- 검수되지 않은 이미지와 라벨 없는 이미지
- 동일 파일 및 동일 내용 이미지 그룹
- 클래스별 데이터 편중과 train/val 분포
- 동일 내용 이미지의 train/val 누수

동일한 이미지 내용은 파일명이 달라도 SHA-256 그룹으로 묶어 같은 split에 배정합니다. 정상/빈 이미지는 의도적인 hard negative로 유지해 배경 오검출을 줄입니다.

## 4. YOLO 검사 경로

YOLO 액션은 클래스, confidence, NMS IoU, 최대 검출 수, ROI, 탐색 순서를 설정할 수 있습니다. ONNX 결과는 confidence로 1차 필터링한 뒤 클래스별 NMS를 적용하고 최대 검출 수로 제한합니다. 판정 결과는 기존 분기, 관찰 기록, 마우스·키보드 액션과 연결됩니다.

권장 데이터 루프는 다음과 같습니다.

1. 실제 대상 창 또는 카메라에서 이미지 수집
2. 작업중 라벨 작성
3. 검수 완료 또는 정상/빈 이미지로 확정
4. 품질 검사 후 YOLO train/val 내보내기
5. 학습 및 ONNX 교체
6. 현장 오검출·미검출 이미지를 다시 수집하는 active-learning 반복

## 5. AOI 검사 경로

AOI는 OK/NG 샘플과 검사 ROI를 사용합니다. 위치 정렬, 전처리, 픽셀 차이, 최소 결함 면적, OK 샘플 편차 기반 적응 허용 맵을 조합하고, 보유한 OK/NG 샘플에 대해 F1 점수가 높은 결함률 임계값을 추천합니다. OK 기준 계산 시 자기 자신과 비교해 점수가 과대평가되지 않도록 leave-one-out 방식으로 보정합니다.

표준 운용 순서는 `카메라·조명 고정 → 검사 ROI 설정 → 여러 OK 샘플 → 실제 NG 샘플 → 자동 보정 → 미등록 샘플 검증 → 실행 액션 연결`입니다.

## 6. 복합 검사 운용

```text
대상 창 또는 카메라
        ↓
공통 검사 프레임
   ├─ YOLO: 부품/결함 위치와 종류
   ├─ AOI: 등록되지 않은 외관 변화
   ├─ 관찰 실행: 판정·점수·ROI 이력
   └─ 라벨 수집: 재학습 데이터
        ↓
분기 / 로그 / HMI 입력 / 재검수 큐
```

YOLO는 학습된 결함을 분류하고 AOI는 미학습 변화를 보완합니다. 두 검사를 순차 액션으로 구성하면 “부품 존재 확인 → 외관 이상 확인 → 결과에 따른 분기” 같은 설비 흐름을 만들 수 있습니다.

## 7. 참고 오픈소스에서 반영한 원칙

| 참고 프로젝트 | 적용한 원칙 |
|---|---|
| Label Studio | 명시적 검수 상태, 이미지 단위 메모, 검수 큐 |
| anomalib | 정상 샘플 기반 이상 점수, 임계값 보정, 미학습 이상 보완 |
| open-aoi | ROI 중심 검사, OK/NG 샘플과 현장 보정 흐름 |
| supervision | confidence 이후 NMS, 검출 수 제한, 일관된 후처리 |
| Packaging Defect Detection | 실제 검사 영상 수집부터 YOLO 판정까지의 폐루프 운용 |

이 프로젝트는 각 저장소의 코드를 복사하지 않고, 검사 설비에 필요한 운용 원칙을 현재 구조에 맞게 구현합니다.
