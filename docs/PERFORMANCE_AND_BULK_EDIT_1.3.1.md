# 고속 캡처·선택 값 일괄 변경 (v1.3.1)

> CPU 회귀 수정과 실제 프로젝트 측정 결과는 [`CPU_OPTIMIZATION_1.3.2.md`](CPU_OPTIMIZATION_1.3.2.md)를 참고하세요. v1.3.2부터 미리보기 전역 제한과 ROI 적응형 Mat 변환이 적용됩니다.

## 리스트 시작 화면 1회 캡처

`설정 > 캡처 부하 최적화 > 리스트 시작 화면 1회 캡처`의 동작은 다음과 같습니다.

1. 목록의 새 사이클이 시작될 때 대상창 전체를 한 번 캡처합니다.
2. 첫 번째 이미지 액션은 자신의 ROI만 잘라 템플릿과 비교합니다.
3. 두 번째 이후 이미지 액션도 각자의 ROI를 사용하지만 화면 원본은 모두 1번의 같은 프레임입니다.
4. v1.4.2부터 `액션 후 화면 갱신`이 켜져 있으면 입력 성공 뒤 새 화면을 캡처하고 남은 항목을 순서대로 계속합니다. 목록 끝에서만 처음으로 돌아갑니다.
5. 해당 설정을 끈 경우에만 같은 프레임으로 목록의 나머지 항목을 끝까지 검사합니다.

스마트 대기는 정지된 같은 프레임을 100ms마다 다시 검사해도 새 정보가 생기지 않습니다. 따라서 이 모드에서는 한 사이클에 한 번 판정하고, 조건이 아직 충족되지 않으면 다음 캡처 사이클에서 다시 확인합니다. 클릭 반응 확인처럼 명시적으로 새 화면이 필요한 별도 검증 기능은 설정했을 때만 추가 캡처를 사용할 수 있습니다.

## CPU를 줄이면서 탐색 속도를 유지하는 구조

- 캡처한 Bitmap을 OpenCV Mat으로 사이클당 한 번 변환합니다.
- 각 ROI는 픽셀을 복사하는 새 Bitmap이 아니라 원본 Mat의 영역 뷰를 사용합니다.
- 템플릿도 파일 변경 전까지 Bitmap과 Mat을 함께 캐시합니다.
- 미리보기 전체 화면 복제는 판정 상태가 바뀌거나 250ms가 지난 경우에만 수행합니다.
- Replay의 같은 실패는 60초에 한 번만, ROI 주변 24px 문맥을 포함해 저장합니다.

29개 ROI를 20회 검사하는 성능 스모크는 다음 명령으로 실행합니다.

```powershell
dotnet run --project artifacts\PerformanceSmoke\PerformanceSmoke.csproj -c Release
```

실제 CPU 수치는 대상창 크기, ROI 크기, 템플릿 크기, 전처리, 화면 변화와 Replay 설정에 따라 달라집니다. ROI는 대상을 놓치지 않는 범위에서 작게 유지하고, 일반적으로 검색 사이클 대기는 30~100ms에서 조정하는 것이 좋습니다.

## 기준 액션 복사와 선택 값 변경의 차이

- `복사`: 한 액션을 기준으로 선택한 설정 그룹 전체를 다른 액션에 복사합니다.
- `변경`: 기준 액션 없이 선택한 액션 모두에서 체크한 필드 값만 바꿉니다.

![선택 액션 설정 값 일괄 변경](../artifacts/bulk-settings-edit-v1.3.1.png)

`Ctrl` 또는 `Shift`로 파일 액션을 선택한 뒤 작업 목록 위의 `변경` 또는 `액션 > 선택 액션 설정 값 일괄 변경`을 누릅니다.

1. 왼쪽에서 `다중 이미지 조건`, `이미지 매칭`, `대기·중복·재시도`, `마우스·기타 액션`, `흐름` 중 필요한 범주를 체크합니다.
2. 오른쪽에는 선택한 범주의 값만 나타납니다.
3. 실제로 바꿀 필드의 `적용`만 체크하고 새 값을 입력합니다.
4. 선택한 액션들의 값이 다르면 `여러 값`으로 표시됩니다. 구체적인 새 값을 고르기 전에는 적용할 수 없습니다.
5. 아래 변경 개수와 대상을 확인한 뒤 적용합니다.

일괄 변경은 액션 이름·ID, 기본 이미지 이름, 다중 이미지 파일 목록, ROI, 추가 액션 시퀀스를 수정하지 않습니다. 입력값 전체를 먼저 검증한 뒤 모든 대상에 적용하므로 잘못된 숫자 때문에 일부 액션만 바뀌는 상태도 방지합니다.
